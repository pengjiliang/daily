# 项目分析与功能路线图

> 更新日期：2026-10-14  
> 本文只记录尚未实现、且对项目后续交付有价值的工作；已实现功能不再重复列入。

## 项目定位与当前范围

这是一个面向私有部署的 AI 知识库项目，包含 Web 前端、NestJS API 服务和 Python AI 服务。当前产品假设是**每家客户独立部署**，企业内部员工可共用部署账号；暂不按 SaaS 多租户模式设计，也不把多角色、组织隔离列为当前必做项。

## 后续待办

### P0：商用交付前需要处理

#### 1. ~~修复知识库文件的直接静态访问~~（已完成）

已实现：服务端仅对 `uploads/avatars` 开放静态访问，知识库文档统一经授权下载接口返回，避免文档绕过登录/共享权限被直接访问（2026-10-18）。

同时，上传侧已增加按文件头（magic bytes）探测真实格式的内容校验，与扩展名白名单对照，伪装扩展名的文件会被拒绝进入解析链路（2026-10-18）。

#### 2. ~~建立可重复的生产部署与升级流程~~（已完成）

已实现：根目录 `docker-compose.yml` 已包含 `db/server/ai-service/web` 完整服务定义，前端经 Nginx 反代访问 API，服务端来源由环境变量控制；`deploy/` 下提供部署手册与本地部署验证指南，包含首次部署、升级、备份与恢复说明，并强调备份 `ENV_ENCRYPTION_KEY`。

### P1：稳定性、维护和数据增长

#### 3. ~~使用数据库迁移管理结构变更~~（已完成）

已实现：Server 端新增基线迁移（`apps/server/src/migrations`），生产默认关闭 TypeORM `synchronize`，启动时自动执行未应用的迁移；AI 服务不再调用 `synchronize()`，只负责扩展与索引（2026-10-18）。

> 前置工作：`ai_settings` 实体已收敛由 Server 端单独管理，AI 服务改为原生 SQL 只读 + 手动解密（2026-10-14）。

#### 4. ~~处理知识库变化后的语义缓存失效~~（已完成）

已实现：文档索引完成或删除后，Server 调用 `POST /ai/cache/invalidate` 清空该用户的语义缓存，避免同类问题命中过期答案（2026-10-14）。

#### 5. 提升向量检索的数据规模适应性

`document_chunks.embedding` 当前以文本保存，检索时再转换为向量参与相似度计算，尚未使用向量列及近似最近邻索引。数据增长后，检索需要处理更多记录，性能应通过真实数据基准确认。

先建立包含文档量、检索延迟和资源用量的基准；确认现有实现成为瓶颈后，再迁移到 pgvector 向量列并建立合适的 ANN 索引，同时明确向量维度与模型切换时的重建策略。大文档分块写入也应采用批量上限，避免单次保存过多记录。

#### 6. 补齐自动化回归验证

仓库目前没有覆盖核心链路的自动化测试。修复权限、索引或数据库流程时，容易引入难以从页面发现的回归。

优先覆盖登录与权限、上传到索引、问答引用、文档共享/下载、模型密钥加解密和数据库迁移。先围绕关键业务链路建立少量稳定的集成验证，再按实际故障补充用例。

### P2：提升知识答案的可核验性

#### 7. 将引用定位到文档内部位置

当前引用能关联到文档及检索片段，但缺少稳定的页码、段落或原文位置元数据，用户难以快速核对较长文档中的依据。

在解析和分块阶段保存可用的位置元数据；对 PDF 优先提供页码定位，对其他格式尽可能定位到段落，并在前端预览中跳转到对应位置。不同格式无法可靠定位时，应展示清晰的降级结果。

## 暂不列入当前路线图

- SaaS 多租户、企业组织与细粒度角色权限：当前按客户独立部署、员工共用账号的范围推进；客户提出集中化 SaaS 需求后再单独评估。
- 额外文档源（网盘、企业协作平台、网页等）、OCR、移动端及更多检索策略：先依据目标客户的实际使用需求排序。
- 继续增加模型与复杂 Agent 能力：在安全、部署、升级和知识答案可核验性达到交付要求前，不作为优先投入。
