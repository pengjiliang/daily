# AI 知识库 本地部署验证指南

本文面向**你（开发者/交付方）**：在你自己的一台电脑上，从零把 Docker 装好，跑起整套系统，
并逐项验证功能是否正常。验证通过后，这套流程就等于替客户提前走了一遍。

> 目标：一台全新的电脑，跟着本文能独立完成「下载 Docker → 启动 → 构建 → 运行 → 验证 → 停止」。

## 一、准备

### 1.1 本机条件

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 10/11 专业版/企业版（支持 Docker Desktop）/ Linux / macOS |
| 内存 | 建议 ≥ 8GB（开发机建议 16GB，Docker Desktop 本身占 2~4GB） |
| 磁盘 | ≥ 20GB 空闲（镜像 + 依赖 + 数据 + 构建缓存） |
| 网络 | 能访问 Docker Hub、npm 源、模型 API（如火山方舟） |
| 模型 Key | 可选；没有也能验证除「问答生成」外的全部功能 |

### 1.2 需要准备的东西

- 项目源码目录（就是 `ai_knowledge_base` 这个文件夹，包含 Dockerfile / docker-compose.yml）
- 你自己的模型 API Key（可选，用于验证问答；没有就先跳过问答那步）
- 一个测试用的文本文件（如 `test.txt`，写几句中文内容）、一张测试图片（验证 OCR）

## 二、下载并安装 Docker（Windows 为例）

### 2.1 Windows 装 Docker Desktop

**第 1 步：下载**

打开浏览器访问 Docker 官网：

```text
https://www.docker.com/products/docker-desktop/
```

点页面上的 **Download for Windows** 按钮，下载 `Docker Desktop Installer.exe`（约 500MB）。

> 如果官网下载慢或打不开，可以用国内镜像站下载，或联系我提供安装包。

**第 2 步：安装**

双击下载的安装包，一路按默认选项（Next → Install）。安装过程中如果提示需要 WSL2，选「是/Install」自动安装。

**第 3 步：启动**

安装完成后，从开始菜单打开 **Docker Desktop**。首次启动会提示接受协议，点 Accept；
然后等右下角（或系统托盘）的鲸鱼图标变成稳定的绿色/蓝色，表示 Docker 引擎已就绪。

> 首次启动可能提示需要启用 WSL2 或重启电脑，按提示操作，重启后重新打开 Docker Desktop 即可。

**第 4 步：确认安装成功**

打开 PowerShell（开始菜单搜索 PowerShell），运行：

```bash
docker --version
```

预期输出类似：`Docker version 27.x.x, build xxxxxxx`（能看到版本号即成功）。

再确认 Compose 插件：

```bash
docker compose version
```

预期输出类似：`Docker Compose version v2.x.x`。

> 如果 `docker compose`（中间有空格）报错，但 `docker-compose`（中间是横杠）能用，说明 Compose 插件没装好，重新安装或升级 Docker Desktop。

### 2.2 Linux 装 Docker（Ubuntu/Debian 为例）

如果验证机器是 Linux，用系统包管理器安装：

```bash
# 安装依赖
sudo apt-get update
sudo apt-get install -y ca-certificates curl

# 添加 Docker 官方源
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# 安装 Docker 与 Compose 插件
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# 验证
docker --version
docker compose version
```

### 2.3 macOS 装 Docker Desktop

同样到 Docker 官网下载 **Download for Mac**（Apple Silicon 选带 ARM 的版本），拖入 Applications 安装，
打开后等鲸鱼图标就绪，验证命令同上。

## 三、准备项目与配置文件

### 3.1 确认项目目录

在终端里进入项目根目录（Windows PowerShell 示例）：

```powershell
cd E:\01_编程开发区\01_项目工程\daily\ai_knowledge_base
```

然后确认目录里有部署文件：

```bash
ls
```

预期能看到 `Dockerfile`、`docker-compose.yml`、`nginx.conf`、`apps`、`packages`、`.env.example`。

### 3.2 生成密钥并创建 .env

项目根目录执行（Windows 的 PowerShell / Git Bash / WSL 都自带 openssl；没有就用下面的替代方案）：

```bash
openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32
```

复制三行输出，分别记为**密钥1 / 密钥2 / 密钥3**。

> Windows 如果没有 openssl 命令：安装 Git for Windows（自带 Git Bash），在 Git Bash 里运行上面命令；或安装 WSL 后在 WSL 里运行。

创建配置文件：

```bash
cp .env.example .env
```

然后编辑 `.env`（Windows 可用记事本，或用 `notepad .env`）：

```bash
JWT_SECRET=<密钥1>
ENV_ENCRYPTION_KEY=<密钥2>
INTERNAL_AI_TOKEN=<密钥3>

# 如果要用模型问答，填你自己的 Key；暂时没有可留空，其余功能照常验证
OPENAI_API_KEY=<你的模型Key，可留空>
OPENAI_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
OPENAI_EMBEDDING_MODEL=doubao-embedding-vision
OPENAI_CHAT_MODEL=doubao-seed-2.0-lite

# 数据库密码改成自己的（本地验证随便设一个强点的）
DATABASE_PASSWORD=change-me-local-test
```

> `.env` 不要提交到 git，`.dockerignore` 已把它排除。

## 四、构建并启动

### 4.1 构建镜像并启动（首次较慢）

在项目根目录执行：

```bash
docker compose up -d --build
```

过程说明：
- 先 **Building**（构建），首次要拉 `node:20`、`pgvector/pgvector:pg16`、`nginx:1.27-alpine` 三个基础镜像，再装依赖、编译，约 5~15 分钟（看网速）
- 然后显示 `Creating network`、`Creating db ... done` 等一排容器创建完成
- 最后回到命令行提示符，表示已在后台运行（-d）

**构建失败排查：**

- 拉镜像超时（`failed to resolve ... timeout`）：网络到 Docker Hub 慢，重试；或给 Docker Desktop 配置镜像加速器（Settings → Docker Engine 加 `registry-mirrors`）。
- `pnpm install` 报网络错误：重试一次；仍失败检查 npm 源（项目 `.npmrc` 用的是 npmmirror）。
- 提示某密钥没配置（`JWT_SECRET: 请先配置...`）：回 3.2 检查 `.env` 是否真的填了。
- 构建到一半断了：重新执行同一条命令，Docker 会缓存已完成步骤继续。

### 4.2 确认四个服务都在运行

```bash
docker compose ps
```

预期看到四行，状态都是 `Up`（running）：

```text
NAME              STATUS
ai-knowledge-base-db-1          Up (healthy)
ai-knowledge-base-server-1      Up
ai-knowledge-base-ai-service-1  Up
ai-knowledge-base-web-1         Up
```

如果某个服务显示 `Restarting`（反复重启），看它的日志：

```bash
docker compose logs server
docker compose logs ai-service
```

常见原因：密钥没配好导致服务启动即退出（日志会写清楚）；数据库还没就绪（等 db 变 healthy 后 server 会自动连上）。

## 五、逐项功能验证

### 5.1 打开页面

浏览器访问：

```text
http://localhost:8080
```

预期看到「用户登录」页面。

### 5.2 注册与登录

1. 点「立即注册」，填用户名（≥3 字符）和密码（≥6 字符）
2. 注册成功跳转登录页，用刚注册的账号登录
3. 登录后进入主页，右上角显示用户名

> 若注册报错，看 `docker compose logs server` 是否有异常。

### 5.3 上传文档并索引

1. 左侧「文档管理」→「上传文档」，选一个测试 `.txt` 或 `.docx`
2. 文件出现在列表，状态先显示「排队/索引中」
3. 等状态变为「已索引」（带绿色对勾或完成徽标），通常几秒到几十秒

验证索引是否真正成功：

```bash
docker compose logs ai-service
```

预期日志里有类似 `Indexed N chunks for upload file ...` 的行。

> 如果一直「排队/索引中」且 ai-service 日志报错，检查 server 与 ai-service 的上传目录是否一致（部署已设为共享卷，正常不会错）。

### 5.4 问答验证（需要有模型 Key）

1. 在对话区输入文档里的一句内容作为问题（例如测试文档写了「今天是晴天」，就问「今天的天气如何？」）
2. 预期看到：检索来源（右侧引用片段，含你上传的文档）→ 流式回答（逐字出现）
3. 回答结束后，点开引用来源能看到你的文档内容

如果没配模型 Key 或 Key 错误，会报「模型调用失败」，这是正常的——其余功能不受影响。

### 5.5 图片 OCR 验证

1. 上传一张含中文文字的图片（如截图或拍照）
2. 等索引完成后，在对话里问图片里的文字内容

预期能识别出图片文字（验证内置 OCR 语言包 + TESSDATA_PREFIX 配置是否生效）。

> 若识别失败，看 ai-service 日志是否报语言包加载错误。正常部署已把 `chi_sim`/`eng` 语言包打进镜像，不应有此问题。

### 5.6 其他页面抽查

- 「知识图谱」：应能看到上传文档对应的节点
- 「使用统计」：应显示文档数/会话数等（问过问题后数字会变）
- 「模型配置」：能打开设置页、能保存（保存时若向量模型变化会触发重建索引）
- 头像：右上角头像下拉可「更换头像」，换完刷新仍保留（验证 /uploads 静态资源代理）

## 六、收尾

### 6.1 停止系统（保留数据）

```bash
docker compose down
```

数据保留在项目根目录 `data/`（数据库 `data/pg`、上传文件 `data/uploads`）。
下次再启动：

```bash
docker compose up -d
```

### 6.2 彻底清理（删除数据，验证完不需要保留时）

```bash
docker compose down -v
```

`-v` 会连数据卷一起删，数据不可恢复，仅确认不要数据时用。

### 6.3 查看日志排错

```bash
docker compose logs -f server
docker compose logs -f ai-service
docker compose logs -f web
```
