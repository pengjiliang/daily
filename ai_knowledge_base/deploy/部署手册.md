# AI 知识库 私有化部署手册

本文面向部署人员。目标是让一套全新的机器（已装 Docker）在 10 分钟内跑起整个系统：
PostgreSQL + 向量检索、后端 API、AI 问答服务、前端页面全部由 Docker 管理，无需手动安装 Node / PostgreSQL / pgvector。

## 一、客户机器需要什么

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Linux（推荐 Ubuntu 22.04+）/ Windows（Docker Desktop）/ macOS |
| 软件 | Docker 与 Docker Compose 插件（`docker compose version` 能输出即可） |
| 内存 | 建议 ≥ 4GB（数据库 + 两个 Node 服务 + Nginx） |
| 磁盘 | 至少 5GB 可用（镜像 + 数据 + 上传文档） |
| 网络 | 安装时可访问 Docker Hub 与模型 API；运行期只需能访问模型 API（客户自己的 Key） |
| 模型账号 | 客户的 OpenAI 兼容 API Key（豆包 / 火山方舟 / OpenAI 等，按用量付费） |

> 首次构建镜像需要联网拉取基础镜像与 npm 依赖；**之后运行不需要外网**（OCR 语言包已内置）。

## 二、目录结构

把项目（或交付的部署包）放到服务器，例如 `/opt/ai-kb`，确认包含：

```text
ai_knowledge_base/
├── Dockerfile
├── docker-compose.yml
├── nginx.conf
├── .env.example          # 配置模板
├── apps/                 # 源码（构建用）
├── packages/
└── data/                 # 运行后自动生成：数据库数据 + 上传文档
```

## 三、配置（第一次部署必做）

### 3.1 生成密钥

在项目根目录执行（Linux/macOS 自带 openssl）：

```bash
# JWT 登录签名密钥：32 位以上随机字符串
openssl rand -hex 32
# 模型密钥加密密钥：必须是 64 位 hex（openssl rand -hex 32 恰好是 64 位）
openssl rand -hex 32
# server 与 ai-service 之间内部通信令牌：32 位以上随机字符串
openssl rand -hex 32
```

### 3.2 写配置文件

```bash
cp .env.example .env
```

编辑 `.env`，**至少修改以下必填项**（示例）：

```bash
# 三把密钥（用 3.1 生成的值替换）
JWT_SECRET=<第一个输出>
ENV_ENCRYPTION_KEY=<第二个输出，64 位 hex>
INTERNAL_AI_TOKEN=<第三个输出>

# 客户自己的模型 API（以火山方舟/豆包为例）
OPENAI_API_KEY=<客户自己的 Key>
OPENAI_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
OPENAI_EMBEDDING_MODEL=doubao-embedding-vision
OPENAI_CHAT_MODEL=doubao-seed-2.0-lite

# 可选：对外访问端口（默认 8080）
WEB_PORT=8080

# 可选：数据库账号（默认 postgres/postgres）
DATABASE_USER=postgres
DATABASE_PASSWORD=<改成强密码>
DATABASE_NAME=ai_knowledge_base
```

> **重要**：`ENV_ENCRYPTION_KEY` 一旦使用必须永久备份——它用于加密用户在设置页保存的模型 API Key，**丢失后已保存的 Key 将无法解密，用户需重新填写**。
> `JWT_SECRET` 与 `INTERNAL_AI_TOKEN` 也必须随机，绝不能使用默认值（服务启动时会强校验并拒绝启动）。

## 四、启动

```bash
cd ai_knowledge_base
docker compose up -d --build
```

首次会构建镜像（拉基础镜像 + 装依赖 + 编译，约 5~15 分钟，取决于网络）。之后启动只需数秒。

查看状态：

```bash
docker compose ps
docker compose logs -f server
docker compose logs -f ai-service
```

## 五、访问与验证

- 浏览器打开 `http://<服务器IP>:8080`（或本机 `http://localhost:8080`）
- 注册账号 → 上传测试文档 → 等索引完成 → 提问，确认能检索并回答
- 头像、文档预览、SSE 流式回答、知识图谱逐一验证

## 六、日常运维

### 备份（建议每天）

数据库与上传文件都在 `data/` 目录：

```bash
# 停写期间备份（简单方式）
docker compose stop server ai-service
tar -czf backup-$(date +%F).tar.gz data/
docker compose start server ai-service

# 在线备份数据库（不停服）
docker compose exec db pg_dump -U postgres ai_knowledge_base > kb-$(date +%F).sql
```

备份至少包括：`data/pg`（数据库）、`data/uploads`（用户文档）、以及三把密钥（`.env` 请一并备份）。

### 升级

```bash
cd ai_knowledge_base
docker compose down      # 先备份（见上）
# 替换为新版文件（保留 .env 与 data/）
docker compose up -d --build
```

`data/` 与 `.env` 保留即可，数据不丢。

### 常见问题

- **页面打不开 / 一直转圈**：看 `docker compose ps` 是否都 Up，`docker compose logs -f server` 有无报错；常见原因是三把密钥没配好导致服务拒绝启动。
- **图片 OCR 识别不出来**：确认镜像内置语言包（`apps/ai-service/*.traineddata`）且设置了 `TESSDATA_PREFIX`，OCR 离线可用。
- **回答提示模型调用失败**：确认 `.env` 的 `OPENAI_API_KEY` / `OPENAI_BASE_URL` / 模型名正确，且服务器能访问该模型 API。
- **改了 .env 不生效**：改完需 `docker compose up -d --build`（密钥变化时）重建容器。
- **想用域名 + HTTPS**：在 Nginx 前加一层反向代理（Caddy / 云负载均衡）终结 TLS，转发到本机 `:8080`。

## 七、安全注意

- 三把密钥必须随机且妥善备份，尤其 `ENV_ENCRYPTION_KEY`。
- 数据库端口 5432 未对外暴露（仅容器内网），不要手动映射到公网。
- 首次注册用户即管理员（单租户、内部共用账号模型），请由部署方先注册并管理账号。
- 生产环境请确认防火墙只开放 `WEB_PORT`。

## 八、客户完整操作清单（一步步照着做）

下面把从零到能用的每一步写全，每步给出**命令**、**预期看到什么**和**出错怎么办**。

### 命令在哪里运行？（先看这一段）

本清单里的命令都写在 `bash` 代码块里（以三个反引号加 bash 开头、三个反引号结尾）。**`bash` 只是代码块的语言标签，不是要你输入的命令**，真正要执行的是代码块里面的命令行内容。

这些命令要在**终端**里运行，不是在浏览器、记事本或 Docker Desktop 界面里。不同系统打开终端的方式：

- Windows：开始菜单搜索 PowerShell（推荐）或命令提示符（cmd），打开后是深色窗口，里面有 `PS C:\Users\xxx>` 或 `C:\Users\xxx>` 提示符，把命令粘贴进去回车执行。
- Linux：打开系统自带的终端（Terminal），提示符通常是 `user@host:~$`。
- macOS：打开终端（Terminal.app），提示符通常是 `xxx@Mac ~ %`。

**在哪个目录运行？** 除了每个步骤里明确写了 cd（进入目录）的命令外，绝大多数命令都要在**项目根目录**运行。项目根目录就是同时包含 Dockerfile、docker-compose.yml、apps、packages 的那个文件夹。

判断当前目录是否正确：运行

```bash
ls
```

如果输出里能看到 Dockerfile 和 docker-compose.yml，说明已经在项目根目录，可以执行 docker compose 开头的命令；如果看不到，先用 cd 进入项目目录（Windows 示例 `cd D:\部署\ai_knowledge_base`，Linux 示例 `cd /opt/ai-kb/ai_knowledge_base`）。

> 一句话记住：docker compose 开头的命令永远要在包含 docker-compose.yml 的目录里运行，否则会报找不到 compose 文件。

### 第 0 步：确认环境

```bash
docker --version          # 预期输出版本号，如 Docker version 24.0.7
docker compose version    # 预期输出 v2.x，如 Docker Compose version v2.24.1
```

- 如果 `docker` 不存在：Windows 装 Docker Desktop；Linux 用系统包管理器安装 docker + docker-compose-plugin。
- 如果 `docker compose`（带空格）报错但 `docker-compose`（带横杠）能用：改用 `docker-compose` 命令，或升级 Docker。
- Windows 上首次启动 Docker Desktop 后需等右下角鲸鱼图标变绿（引擎就绪）。

### 第 1 步：拿到项目并放好位置

把交付的项目目录放到服务器，例如：

```bash
mkdir -p /opt/ai-kb && cd /opt/ai-kb
# 把 ai_knowledge_base 整个目录拷进来，或按交付方说明解压/克隆
ls   # 预期看到 Dockerfile / docker-compose.yml / nginx.conf / apps / packages / .env.example
```

> 如果交付方给的是压缩包，先解压，确保里面有 `Dockerfile` 和 `docker-compose.yml`。

### 第 2 步：生成三把密钥

```bash
cd ai_knowledge_base
openssl rand -hex 32   # 第 1 把：JWT_SECRET
openssl rand -hex 32   # 第 2 把：ENV_ENCRYPTION_KEY（64 位 hex）
openssl rand -hex 32   # 第 3 把：INTERNAL_AI_TOKEN
```

- 每执行一次输出一串 64 位十六进制字符，**分别复制保存**，不要混。
- Windows 没有 openssl 时：用 PowerShell / Git Bash / WSL 里的 `openssl`，或让交付方提供生成工具。
- **这三串值一定要备份**（密码管理器或纸上），尤其是第 2 把。

### 第 3 步：创建配置文件

```bash
cp .env.example .env
nano .env   # 或用 vim / 记事本编辑
```

把第 2 步的三串值分别填到对应行，并填模型信息：

```bash
JWT_SECRET=<第1把>
ENV_ENCRYPTION_KEY=<第2把>
INTERNAL_AI_TOKEN=<第3把>

OPENAI_API_KEY=<你自己的模型Key>
OPENAI_BASE_URL=https://ark.cn-beijing.volces.com/api/v3  # 以火山方舟为例
OPENAI_EMBEDDING_MODEL=doubao-embedding-vision
OPENAI_CHAT_MODEL=doubao-seed-2.0-lite

DATABASE_PASSWORD=<改成你自己的强密码>
```

> 模型 Key 从你的模型供应商后台获取（火山方舟/OpenAI 等），每个企业用自己的账号，费用自理。
> 暂时没有模型 Key 也可以先启动（界面、上传文档、知识库功能可用），只是问答会报模型调用失败。

### 第 4 步：首次构建并启动

```bash
docker compose up -d --build
```

预期：
- 终端先显示 Building（构建，约 5~15 分钟，首次拉镜像和装依赖较慢）
- 然后显示一排 `Creating ... done` / `Starting ... done`
- 最后回到命令行提示符（-d 是后台运行）

构建/启动失败排查：
- **拉镜像超时**（`failed to resolve ... timeout`）：网络到 Docker Hub 慢，重试或配置镜像加速器。
- **pnpm install 报错**：多半是网络到 npm 源的问题，重试一次；仍失败联系交付方。
- **提示某密钥没配置**（`JWT_SECRET: 请先配置` 之类）：回第 3 步检查 `.env` 是否真的填了值。
- 构建到一半中断：重新执行同一条命令即可（Docker 会缓存已完成步骤）。

### 第 5 步：确认服务都起来了

```bash
docker compose ps
```

预期：`db`、`server`、`ai-service`、`web` 四个服务都是 `Up`（状态列 running）。
如果 `server` 或 `ai-service` 反复重启（`Restarting`）：

```bash
docker compose logs server      # 看后端日志
docker compose logs ai-service  # 看 AI 服务日志
```

常见：密钥没填对 → 服务启动即退出（日志会提示）；数据库没就绪 → server 连不上（等 db 健康后会自动重试）。

### 第 6 步：访问并注册

浏览器打开 `http://<服务器IP>:8080`（本机验证时用 `http://localhost:8080`）。
预期看到登录页 → 点「注册」创建第一个账号。

- 打不开：确认防火墙放行 8080 端口；`docker compose ps` 确认 web 容器 Up；本机验证用 localhost 不涉及防火墙。

### 第 7 步：上传文档并问答验证

1. 登录后左侧「文档管理」→ 上传一个 `.txt` 或 `.docx` 测试文件
2. 等文件状态变为「已索引」（右侧有状态徽标，通常几秒到几十秒）
3. 在对话里提问文档里的内容，确认回答能引用该文档
4. 再试：上传一张图片（OCR 是否识别）、查看「知识图谱」页面是否有节点

- 上传后一直「排队/索引中」：`docker compose logs ai-service` 看索引日志。
- 问答报「模型调用失败」：回第 3 步确认模型 Key / BaseURL / 模型名正确，且服务器能访问该地址。
- 图片识别不出来：看日志是否报 tesseract 加载语言包错误；正常部署已内置语言包，不应有此问题。

### 第 8 步：投入使用

把访问地址（`http://<服务器IP>:8080`）告诉公司同事即可。账号可自行注册；这是单租户部署，同一套系统内所有账号共享同一份知识库（文档按上传账号隔离可见，建议由管理员统一维护文档）。

### 日常维护命令速查

```bash
docker compose ps                       # 看状态
docker compose logs -f server           # 实时看后端日志
docker compose logs -f ai-service       # 实时看 AI 服务日志
docker compose restart server           # 重启后端
docker compose down                     # 停全部（数据保留在 data/）
docker compose up -d                    # 再次启动
docker compose up -d --build            # 升级/改配置后重建
```
